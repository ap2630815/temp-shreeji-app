TABLE: labour_groups
----------------------------------------------------------------------
column                    | type                     | constraints
----------------------------------------------------------------------
id                        | INTEGER                  | PRIMARY KEY, AUTO INCREMENT
group_name                | VARCHAR(30)              | NOT NULL
group_name_gu             | VARCHAR(30)              | -
village_id                | INTEGER                  | FOREIGN KEY villages(id)   (the group is shown everywhere as "group name - village name")
description               | TEXT                     | -
created_at                | TIMESTAMP WITH TIME ZONE | NOT NULL, DEFAULT now()

Table constraints / indexes:
  UNIQUE uq_labour_groups_name_village (group_name, village_id)   -- the same group name may exist in different villages
  UNIQUE INDEX uq_labour_groups_name_no_village (group_name) WHERE village_id IS NULL   -- groups saved before villages were added
  INDEX ix_labour_groups_village_id (village_id)
Display name (app): "group name - village name"; Gujarati "group name (Gujarati) - village name (Gujarati)". Every list, drop-down, statement and
analysis uses it (LabourGroup.display_name / display_name_gu). The Add / Edit form needs the village; old groups without one show the plain name
until their village is picked.

UPI NUMBER RULE (every master with a UPI column: farmers, labours, brokers, empty bag sellers / movers, transporters,
trucks (owner and driver), stockyards (owner))
----------------------------------------------------------------------
- The UPI number is stored only when it is DIFFERENT from the mobile number. Blank = "the UPI is the mobile number".
- Add and Edit forms: the label reads "UPI number (if different from mobile)". If the value typed equals the mobile it is saved blank
  (app/services/upi.py drop_upi_same_as_mobile, applied in app/api/masters.py).
- Wherever the UPI is needed (the Pay page shows "UPI: number" or "UPI (same as mobile)") the application uses effective_upi():
  the stored UPI, otherwise the mobile number. Labour groups and industries have no UPI column, so no UPI line shows for them.
